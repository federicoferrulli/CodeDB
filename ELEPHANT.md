# ELEPHANT.md — Guida di sviluppo di CodeDB

CodeDB è un ambiente per esplorare schemi, eseguire query e modificare dati su MongoDB, MySQL e PostgreSQL. Lo stesso workbench gira nel browser, in Electron e in una WebView Android. Anche un client MCP può usare le strategie del server. Una modifica apparentemente locale, come il modo di leggere la chiave di una riga, può quindi cambiare l’editing nella griglia, un’importazione e uno strumento usato da un agente.

Questa guida segue le operazioni attraverso il codice. I collegamenti portano ai sorgenti da modificare, ai test che descrivono il contratto o alle istruzioni specialistiche. Per una prima modifica alla griglia, parti dal [percorso di una richiesta](#dal-clic-alla-risposta). Per indagare una segnalazione, parti da [errori e diagnosi](#errori-e-diagnosi).

Per esplorare gli stessi contratti come grafo, apri l’[atlante interattivo](ELEPHANT.html). Per un agente, il [grafo JSON](ELEPHANT.json) offre punti di ingresso per attività. La chiave `entrypoints["edit-cell"].steps`, per esempio, contiene gli ID dei soli nodi da leggere per lavorare sul salvataggio di una cella. I campi `sources` e `tests` di ciascun nodo portano alle verifiche nel repository.

## Orientarsi nel repository

Una **connessione** è una configurazione riutilizzabile. Una **sessione** è il collegamento vivo a un motore e appartiene a un tab di connessione. All’interno del tab si aprono **schede** per tabelle, collezioni e documenti Query. La parola **database** nell’albero indica uno schema su PostgreSQL. Per raggiungere un altro database fisico PostgreSQL occorre aprire la connessione a quel database. Questa distinzione determina il bersaglio delle letture, delle scritture e dei permessi. ## Avvio e ciclo di vita

Per lavorare da un checkout con il lockfile, usa la linea Node 24 impiegata dalla CI e dall’immagine Docker. Per avviare il workbench servono le dipendenze Node. Puoi esplorare la UI prima di configurare una connessione DB. Il server web usa per impostazione iniziale `127.0.0.1:3030`. [Manifest npm](package.json) · [Dockerfile](Dockerfile) · [CI](.github/workflows/release.yml)

```sh
npm ci
npm run dev
```

`npm start` avvia il server senza il watcher. Se cambi un file in `ui/`, usa `npm run dev:ui` in un secondo terminale, oppure `npm run build:ui` per una compilazione singola. `npm run typecheck:ui` controlla i tipi. Gli ESM in `public/js/` sono serviti direttamente. `npm run start:rbac` carica `.env` con `--env-file` e usa il valore configurato di `CODEDB_RBAC`. Il control plane richiede il proprio MongoDB quando RBAC è attivo. Nel repository il riferimento condivisibile per i nomi delle variabili è il file di esempio. [Build UI](tools/build-ui.mjs) · [Configurazione di esempio](.env.example)

`require('./server')` espone una facciata caricabile senza aprire porte. `createServer({config, dependencies})` crea un’istanza con le sue sessioni, quote, lock e dipendenze. La configurazione combina una copia dell’ambiente con `config.env`, risolve i percorsi e valida porta e URL pubblico. Per istanze di test distinte usa percorsi distinti anche per connessioni, backup, audit e risultati. `PORT: 0` consente al sistema di assegnare una porta libera. Lo stato in memoria per istanza da solo non isola i file su disco. [Configurazione](server/configurazione.js) · [Dipendenze sostituibili](server/dipendenze.js) · [Esempio completo di istanza isolata](docs/server-modulare.md)

| Se devi isolare o localizzare… | Configurazione nel server da sorgenti |
| --- | --- |
| Profili di connessione e vault | `CODEDB_CONNECTIONS_FILE` sceglie il file INI locale. Il vault risiede accanto a quel file. `CODEDB_CONNECTIONS_DIR` sceglie la directory degli INI per owner. |
| Audit e impostazioni MCP | `CODEDB_UI_AUDIT_FILE`, `CODEDB_MCP_AUDIT_FILE` e `CODEDB_MCP_SETTINGS_FILE` hanno percorsi distinti. Il log di attività di un canale e le impostazioni del gateway servono scopi diversi. |
| Copie persistenti e risultati temporanei | `CODEDB_BACKUPS_DIR` sceglie la radice dei backup. I percorsi dei client applicativi sono confinati alla radice autorizzata e, con RBAC, allo spazio del tenant. `CODEDB_SCRIPT_RESULTS_DIR` sceglie il deposito temporaneo delle schede dei risultati. |

Per il valore effettivo considera anche gli override del launcher. Per una fixture, fornisci i percorsi prima di costruire l’istanza. [Risoluzione dei percorsi](server/configurazione.js) · [Policy delle destinazioni di backup](backup/lib/policy.js)

`await start()` completa i controlli di rete e l’inizializzazione prima di risolvere. `await stop()` è idempotente, chiude l’ammissione di nuovo lavoro, drena le attività accettate e libera sessioni, tunnel, depositi, MCP e control plane. Alla fine completa l’audit. Per ripartire si crea una nuova istanza. Il launcher CLI possiede i segnali del processo. Un modulo condiviso deve lasciare al chiamante il controllo su listener di processo e terminazione. [Ciclo di vita](server/createServer.js) · [Launcher CLI](bin/codedb.js) · [Gestione del processo](server/processo.js)

## Dal clic alla risposta

### Leggere una pagina

1. `runQuery()` in `grid.js` raccoglie database, collezione, condizione, ordinamento e pagina. Congela il bersaglio della richiesta e invia `collection:find` con `deferCount`. L’utente può cambiare scheda appena parte la lettura. [Griglia](public/js/grid.js) · [Coerenza delle richieste](public/js/coerenza-richieste.js)
2. `emit()` inserisce il `tabId` e conserva il riferimento al tab di origine. Un `tabId` esplicito, per esempio in uno split, ha precedenza. Socket.IO trasporta il comando e il suo acknowledgment. Il risultato ordinario ha forma `{ ok: true, ... }` oppure `{ ok: false, error }`. Gli avanzamenti di uno script e i cambiamenti dello schema hanno invece eventi push distinti. [Trasporto client](public/js/trasporto.js) · [Contesto del socket](server/socket.js)
3. Sul server `delegate` recupera la sessione dalla mappa del socket, verifica la capability e prepara il contesto che può arrivare alla strategia. La registrazione reale del comando è `lifecycle.delegate('collection:find', (strategy, p) => strategy.collectionFind(p.db, p.coll, p))`. La strategia protetta applica le regole del motore, i permessi e i limiti della lettura. [Handler dati](server/eventi-dati.js) · [Preparazione del payload](db/payloadEsecuzione.js) · [Apertura della strategia](server/connessioni.js)
4. Il client applica le righe allo stato o allo snapshot che ha avviato la richiesta. `res._state` punta allo stato d’origine, mentre `state` segue il tab attivo al momento dell’accesso. Prima di ridisegnare controlla anche documento, bersaglio e richiesta corrente. Una risposta vecchia sullo stesso tab può essere già superata da un nuovo filtro. [Trasporto](public/js/trasporto.js) · [Gestione delle pagine obsolete](test/e2e-pagine-obsolete.js)
5. La griglia mostra subito la pagina. Se manca il totale, chiede `collection:count` con lo stesso filtro. Totale esatto, stima, conteggio pendente e scaduto hanno significati diversi. A scadenza il risultato può essere `{ total: null, timedOut: true }`. Conserva le righe e mostra `?`. Un totale ignoto vale anche per la paginazione e per le azioni massive. [Regole della griglia](public/js/grid.js) · [Limiti e timeout del conteggio](db/tetti.js)

### Modificare una cella

`salvaCampi()` in `inlineEdit.js` invia `doc:update` con `{ tabId, db, coll, id: idOf(doc), set }`. L’editor cattura il bersaglio quando si apre. `idOf()` usa i metadati della riga restituita dal server, anche con una PK composta. Per l’input inline ordinario vengono eliminate alla conferma solo le bozze ancora uguali a quelle catturate prima dell’invio. In caso di errore restano disponibili per la correzione. La griglia rilegge la pagina se il bersaglio è ancora visibile, altrimenti lo marca da aggiornare. Una vista con una propria callback può gestire il refresh. L’editor geometrico e il selettore FK riusano il percorso di scrittura e gestiscono la propria interazione. [Editing inline](public/js/inlineEdit.js) · [Identità delle righe](public/js/righe.js) · [Handler `doc:update`](server/eventi-dati.js)

### Durata di una sessione e lavori concorrenti

Anche l’apertura è asincrona. Gli eventi storici `mongo:connect` e `mongo:disconnect` servono le connessioni dei tre motori. Apertura e chiusura dello stesso tab passano per lo stesso lock. Se il client sparisce durante il collegamento al DB, la nuova strategia e l’eventuale tunnel vanno rilasciati anche se la sessione non è ancora entrata nella mappa. Alcune operazioni, per esempio `uml:apply`, trattengono una *lease*, un riferimento che rinvia il rilascio delle risorse finché il lavoro accettato le usa. Acquisiscila prima del lavoro e rilasciala in `finally` nei percorsi che seguono questa convenzione. [Eventi di connessione](server/eventi-connessioni.js) · [Gestione delle lease](server/socket.js) · [Esempio UML](server/eventi-dati.js)

### Registrare un evento

| Tipo di operazione | Meccanismo | Responsabilità di chi lo aggiunge |
| --- | --- | --- |
| Azione su dati o schema | `lifecycle.delegate` | Restituire il risultato del dominio. Classificare evento e metodo, dichiarare il bersaglio e lasciare al wrapper controlli comuni, audit e pulizia del `runId`. |
| Azione amministrativa | `lifecycle.amministrativo` | Registrare l’evento in `EVENTI_AMMINISTRATIVI`, scegliere il permesso amministrativo corretto nell’handler e produrre l’ack previsto. |
| Operazione lunga | `lifecycle.operazioneLunga` | Dichiarare la politica in `OPERAZIONI_LUNGHE`. Stabilire chi possiede l’operazione e come si osservano avanzamento, autorizzazione, termine e recupero. |

`safeOn` è il livello comune che valida la forma del payload, rivalida il principal, intercetta gli errori e rende monouso l’ack. Esistono eccezioni dichiarate che lo usano direttamente. Per estendere il protocollo, registra l’handler in `server/eventi-*.js`, confrontalo con la famiglia vicina e aggiorna il catalogo di compatibilità. I test confrontano l’elenco effettivamente registrato con nomi e famiglie attesi. [Decisione sulle famiglie](docs/adr/0001-tre-famiglie-di-evento.md) · [Politiche di audit](server/audit.js) · [Catalogo degli eventi](test/server-eventi-attesi.json) · [Test di registrazione](test/unit-registrazione-eventi.js)

## Errori e diagnosi

**Conserva l’errore del driver fino al punto che lo sa spiegare.** Un `Error` con `code`, `codeName`, SQLSTATE o posizione contiene informazioni che `throw new Error(err.message)` può perdere. Il delegato aggiunge quando disponibile `err._ctx` con motore, database e collezione. `errMsg()` passa errore e contesto a `spiegaErrore()`. L’editor di query conserva inoltre la posizione separatamente dal testo. [Uscita del server](server/errori.js) · [Regole di traduzione](db/errors.js) · [Propagazione nell’ack](server/socket.js)

`descriviErrore()` prova le regole di riconoscimento. Per una condizione nota, il messaggio italiano spiega l’accaduto, suggerisce un’azione e include il dettaglio tecnico quando serve. Per esempio, `ECONNREFUSED` con host e porta indirizza al servizio in ascolto e alla porta pubblicata. Una violazione di unicità indirizza al dato o all’indice coinvolto. Un errore già spiegato conserva una sola indicazione «Cosa fare». Un errore sconosciuto conserva il proprio messaggio. `redigiUri()` rimuove le credenziali e oscura query string e frammenti delle URI anche nel caso sconosciuto. [Regole e ordine di riconoscimento](db/errors.js) · [Casi di prova](test/unit-errors.js)

| Situazione | Comportamento da preservare |
| --- | --- |
| Valore rifiutato in un form o in una cella | Collega il feedback al campo o alla vista che ha generato l’errore. Conserva la bozza, rendi leggibile il rimedio e lascia disponibile il dettaglio. |
| Errore SQL con posizione attendibile | `queryError` trasporta un intervallo con inizio incluso e fine esclusa. La UI usa offset UTF-16 da zero. PostgreSQL conta caratteri da uno. Per gli script occorre anche l’offset dell’istruzione nel documento. Quando manca una posizione esplicita, si può evidenziare un frammento riconoscibile e univoco. Negli altri casi si mostra il solo messaggio. |
| Chiusura del tab durante la richiesta | Per richieste legate al tab (`bindTab: true`) il client rifiuta con `AbortError` e codice `TAB_CLOSED`. Libera listener e stato della vista originaria. Un’operazione registrata con `bindTab: false` può sopravvivere alla chiusura. |
| Connessione persa durante una scrittura | L’esito può essere incerto anche se cade l’ack. `executeWithReconnect()` può ristabilire la connessione e segnalare `operationOutcomeUnknown`. Prima di risottomettere l’operazione, verifica lo stato sul DB o nel registro dell’operazione. |
| Conteggio o metadati ausiliari indisponibili | Conserva la pagina già letta. Mostra «sconosciuto» o consenti di ritentare. Zero righe o zero relazioni sono risposte valide con un significato diverso. |
| Errore dopo una modifica parziale | L’operazione deve rendicontare cosa è stato applicato, la fase fallita e l’eventuale recupero. La ricezione dell’ack iniziale documenta l’accettazione della richiesta. |

Il caso di riconnessione automatica del client è più circoscritto. Quando **il server dichiara che manca la sessione** e il tab usa una connessione salvata, `emit` può riaprirla per nome e ritentare una volta. Una risposta persa a comando già inviato richiede le regole sull’esito incerto. La scelta influisce sull’integrità dei dati quanto una transazione. [Trasporto e opzioni di disconnessione](public/js/trasporto.js) · [Riconnessione server](server/connessioni.js) · [Intervalli di errore](public/js/query-error.js) · [Feedback contestuale](public/js/avvisi.js)

La differenza tra un fallback e un errore da propagare dipende da cosa resta utilizzabile. Se il worker delle statistiche si interrompe, lo stesso calcolo può terminare localmente. Se fallisce la verifica finale di un import, il dato sulla destinazione è proprio ciò che doveva essere verificato. Quel fallimento entra nel percorso di recupero. Un `catch` che restituisse un successo vuoto cancellerebbe questa distinzione. [Fallback dei calcoli](public/js/calcoli.js) · [Verifica finale dell’import](db/importPlan.js)

**Per aggiungere una diagnosi**, parti da un codice reale del driver e dal messaggio ripulito. Aggiungi la regola nell’ordine appropriato, poi esercita il caso riconosciuto, uno simile ma diverso, la seconda applicazione del formatter e un’URI sintetica contenente parti riservate. Se il problema riguarda una query, verifica anche una riga successiva alla prima e un carattere fuori dal piano multilingue di base, per esempio un emoji prima dell’errore. [Test degli errori](test/unit-errors.js) · [Test degli offset](test/unit-query-error.js) · [Prova dell’evidenziazione nell’editor](test/e2e-query-error-mark.js)

## Strategie, identità e tipi

`DbFactory.getStrategy()` costruisce la strategia e la avvolge con `conTetti()`. Il tipo assente nelle vecchie connessioni significa MongoDB. `postgres` è un alias di `postgresql`. Quando il server apre una sessione, aggiunge la strategia autorizzante. La classe base raccoglie operazioni comuni come `collectionFind`, `docUpdate` e `dbSchema`. I moduli specifici di un motore si possono installare sul suo prototipo con `definisciMetodi`, che conserva i descrittori dei metodi di classe. Un’operazione interna a SQL→Mongo appartiene all’adattatore Mongo. [Factory](db/DbFactory.js) · [Contratto](db/DbStrategy.js) · [Installazione dei metodi](db/prototipoStrategia.js) · [Test di architettura](test/unit-architettura-modulare.js)

| Motore | Cosa significa il bersaglio | Dettaglio che cambia l’implementazione |
| --- | --- | --- |
| MongoDB | Database, collezione, documento identificato da `_id` | Lo schema può essere campionato. Gli array e i campi rari possono cambiare ciò che si osserva. BSON comprende tipi che il JSON standard perde. [Strategia MongoDB](db/MongoDbStrategy.js) |
| MySQL | Database, tabella, riga | Il pool usa `mysql2`. Anche nel passaggio di una sola riga contano tipo dichiarato, segno, precisione e chiave. Le DDL possono produrre commit impliciti. [Strategia MySQL](db/MySqlStrategy.js) |
| PostgreSQL | Schema nel database fisico della connessione, tabella, riga | Il pool usa `pg`. Qualifica lo schema quando costruisci i riferimenti. `vendite."Ordini"` e `vendite.ordini` possono identificare tabelle diverse. [Strategia PostgreSQL](db/PostgreSqlStrategy.js) |

**Valori e identificatori seguono due percorsi.** Per i valori usa i parametri del driver. Per nomi di schemi, tabelle e colonne usa gli helper di quotatura del dialetto. Il completamento, il trascinamento dal navigatore e le query generate devono risolvere lo stesso nome. Un filtro strutturato usa `{ condizioni: [{ campo, operatore, valore }], unione: 'e' }`. Per la ricerca globale la UI esprime invece l’intenzione `contieneOvunque`. La strategia cerca nei valori dei campi rilevati, anche annidati. Un campo MongoDB raro può entrare nel catalogo solo dopo essere stato osservato. [Identificatori](public/js/identificatori.mjs) · [Filtro](db/filtro.js) · [Ricerca](db/ricercaGlobale.js) · [Decisione sulla ricerca globale](docs/adr/0002-la-ricerca-globale-appartiene-alle-strategie.md)

**Il valore mostrato, l’identità della riga e il payload di scrittura hanno ruoli distinti.** Per SQL il server può restituire `rowIds` e `columnMeta` accanto a `docs`. `preparaRighe()` associa identità e metadati agli oggetti con una `WeakMap`. Così una colonna dell’utente chiamata `_id` rimane un dato ordinario, una PK composta resta intera e una colonna generata può essere esclusa dagli aggiornamenti. Per la riconciliazione dei backup l’identità stabile può essere `_id`, la PK o un vincolo univoco interamente non nullo. Segui la scelta del percorso interessato prima di abilitare un aggiornamento o un merge. [Metadati della griglia](public/js/righe.js) · [Identità nel backup](backup/lib/identity.js)

### Un valore da seguire fino al disco

L’intero `9007199254740993` supera la precisione di `Number`. Un `Long` BSON con questo valore attraversa il trasporto come `{"$numberLong":"9007199254740993"}`. `serializza()` usa la forma semplice quando è esatta e conserva l’involucro per i `Long` che la perderebbero. Per SQL il confine fra driver e protocollo riconosce numeri esatti e binari con i relativi metadati. Una conversione prematura con `Number()` può produrre una cifra diversa prima ancora che intervenga il driver. [EJSON Mongo](db/mongoEjson.js) · [Valori SQL](db/sqlValori.js) · [Editor dei valori esatti](public/js/valori-esatti.js)

Per introdurre un tipo, seguilo attraverso lettura, visualizzazione, editing, copia e incolla, inserimento, export e ripristino nei formati che lo rappresentano. Verifica con un valore limite e una rilettura indipendente dal DBMS. Per i binari confronta i byte, per i decimali confronta tutte le cifre, per una data verifica anche la precisione disponibile. I campi assenti, `null`, `false` e `""` comportano azioni di scrittura diverse. Nel formatter JSON/BSON i token originali consentono di indentare o minificare senza arrotondare valori o perdere la sintassi shell. [Inserimento tipizzato](db/insertValues.js) · [Formatter JSON/BSON](public/js/json-bson.js) · [Test dei tipi di trasferimento](test/unit-transfer-types.js) · [Matrice di fedeltà](docs/matrice-fedelta-export-import.md)

GeoJSON è la forma di scambio delle viste cartografiche. MySQL spatial, PostGIS `geometry`/`geography` e i tipi geometrici nativi PostgreSQL hanno percorsi distinti. La rappresentazione di un punto sulla mappa da sola non determina il suo sistema di riferimento. Nelle modifiche che richiedono lo SRID originale, `modificaConSrid()` può leggere il valore sotto lock nella transazione e rifiuta una conversione ambigua. Una prova di round trip deve confrontare coordinate **e** SRID. [Geometrie](db/geometry.js) · [Geometrie native PostgreSQL](db/pg-geo-nativo.js) · [Modifica con SRID](db/sridModifica.js)

## Query, script e annullamento

`executeQueryCode()` riceve il contesto di esecuzione preparato dal server. `runId` identifica il lavoro, `opHandle` conserva i riferimenti con cui annullarlo sul motore, e la sessione stabilisce identità e destinazione. I campi affidabili vengono ricostruiti al confine. L’editor deduce dal testo la lingua dei suggerimenti, mentre il server verifica che il motore scelto sia coerente con la connessione reale. [Orchestrazione](server/query.js) · [Contesto di esecuzione](db/payloadEsecuzione.js)

| Percorso | Chi interpreta l’istruzione | Contratto rilevante |
| --- | --- | --- |
| SQL nativo MySQL / PostgreSQL | Il DBMS attraverso il proprio driver | Sessione per tab per transazioni, variabili, tabelle temporanee e comandi successivi. Le istruzioni della stessa sessione SQL sono serializzate. Il runner degli script ha un contesto separato. [Sessioni SQL](db/sqlSessione.js) · [Guida SQL nativo](docs/sql-nativo.md) |

Gli script SQL vengono suddivisi secondo il dialetto, tenendo conto di stringhe, commenti e blocchi. Un semplice `split(';')` spezzerebbe anche il corpo di una routine. **Un limite deve avere un esito osservabile.** Le letture della griglia possono dichiarare `truncated`. Il percorso delle query libere rispetta un `LIMIT` esplicito e segnala come errore un risultato incompleto per superamento del budget di memoria. Il valore iniziale di `CODEDB_MAX_RESULT_BYTES` è 32 MiB. I tempi predefiniti distinti di find, aggregate e count sono rispettivamente 30, 120 e 5 secondi. L’adattatore limita il lavoro alla sorgente, per esempio smettendo di consumare un cursore. Il wrapper copre anche adattatori che ignorano il limite. Il suo watchdog può smettere di attendere mentre il database sta ancora lavorando. ## Autorizzazioni, vault e audit

### Dove si prende la decisione

Con RBAC attivo, `POST /auth/login` restituisce un token UI opaco. Il client lo presenta nell’handshake Socket.IO. Il control plane MongoDB conserva utenti, ruoli, grant, API key e sessioni, con hash dei token. Il **principal** è l’identità effettiva dell’operazione. Il **grant** lega capability e scope a una connessione. Una chiave API può avere un limite aggiuntivo sulle connessioni. La rivalidazione permette a revoche e modifiche dei permessi di avere effetto anche su connessioni applicative già aperte. [Gestione dell’identità](server/identita.js) · [Control plane](auth/AppStore.js) · [Token](auth/sessions.js)

- Per un evento sui dati, `EVENT_CAPABILITY` permette un controllo preliminare. `METHOD_CAPABILITY` e `guardStrategy` applicano la regola sulla strategia anche da altri ingressi, per esempio un Virtual JOIN o MCP. I metodi pubblici aggiunti vanno classificati. [Tabelle delle capability](auth/capabilities.js) · [Proxy](auth/guardStrategy.js) · [Prova di copertura](test/unit-tabella-autorizzazioni.js)
- Per SQL libero, il perimetro dipende dalle tabelle effettivamente citate. Filtro e ordinamento strutturati evitano di accettare frammenti arbitrari dove è richiesto uno scope. La protezione delle letture include, sui percorsi previsti, transazioni `READ ONLY` lato DBMS. Il controllo dell’I/O su file è una verifica distinta. [Riferimenti SQL](auth/sqlTables.js) · [Clausole strutturate](auth/sqlClause.js) · [Regole della strategia](auth/guardStrategy.js)
- Un backup che usa un client nativo opera sull’intera connessione. `canWholeConnection` verifica capability e ampiezza dello scope. `canAdminTenant` disciplina le operazioni sul tenant, `isInstallAdmin` quelle su risorse condivise dell’installazione, tra cui il vault. Mantieni questa distinzione anche quando la UI nasconde un comando. [Decisioni di autorizzazione](auth/permissions.js) · [Handler di backup](server/eventi-backup.js)

### Credenziali, connessioni salvate e tunnel

Con vault v2 protetto da passphrase, i segreti sono cifrati con AES-256-GCM. Una chiave dati casuale (DEK) cifra i campi. `scrypt` deriva dalla passphrase la chiave che protegge la DEK. In `vault.json` risiede la chiave avvolta, nei file INI i campi delle connessioni. `rewrapDataKey()` permette di cambiare passphrase aggiornando l’involucro. Il codice gestisce migrazione v1, sblocco, reset e installazioni senza cifratura configurata. I file INI possono quindi contenere segreti in chiaro. La UI include un avviso per questo stato. [Primitive crittografiche](db/vault.js) · [Migrazione e stato del vault](server/vault.js) · [Verifica del ciclo di vita](test/e2e-vault-passphrase.js)

Se aggiungi un campo alla configurazione salvata, decidi se appartiene a `SECRET_FIELDS`. La URI completa, il materiale della chiave SSH e le passphrase richiedono questo trattamento. Verifica lettura, salvataggio senza reinserire il segreto, import/export delle connessioni e lettura dalla CLI di backup. Quest’ultima usa lo stesso modulo crittografico e apre il deposito in sola lettura. Con RBAC, i file delle connessioni risiedono nello spazio del rispettivo owner. Per il ripristino della sessione browser basta il riferimento `{ saved: nome }`. [Vault server](server/vault.js) · [Lettore CLI](backup/lib/connstore.js) · [Ripristino nel browser](public/js/session-restore.js)

L’apertura di un tunnel lega la verifica della chiave host alla connessione. Un pin già presente deve corrispondere. Al primo uso, per una connessione salvata il pin può essere persistito prima di inviare le credenziali. Negli altri casi il flusso può richiedere l’approvazione dell’impronta. La modalità strict richiede un pin preconfigurato. Se fallisce la successiva connessione al DB, chi ha aperto il tunnel deve chiuderlo insieme alla strategia parzialmente inizializzata. [Apertura della sessione](server/connessioni.js) · [Verifica della chiave host](db/SshTunnel.js) · [Supporto delle chiavi](db/SshKey.js)

### Che cosa lascia traccia

Le azioni UI e MCP hanno registri separati. `auditActor()` aggiunge i riferimenti necessari a filtrare per tenant e soggetto. La classificazione considera l’operazione effettiva, compresi esito, errore e conteggi disponibili. L’audit di una query è distinto dal progresso temporaneo sul socket. Le letture automatiche di aggiornamento possono essere escluse dal registro dell’attività utente. Per un nuovo evento definisci anche cosa deve vedere il lettore autorizzato in caso di errore. Limita il payload ai dettagli richiesti dalla politica dell’evento. URI, credenziali e byte di un trasferimento non sono descrizioni di audit. [Politiche e classificazione](server/audit.js) · [Coda, rotazione, salute e flush](db/AuditLog.js) · [Attività MCP](mcp/Activity.js)

**Trasporto dei file.** Il socket governa comandi, autorizzazione e stato. Il servizio HTTP degli artefatti usa ticket brevi legati alla risorsa, all’attore e al tenant, blocchi con offset e SHA-256, e un download finalizzato con `ETag` e `Range`. Un blocco ripetuto identico può essere riconosciuto senza duplicarlo. Il wizard di import database ha anche propri eventi `database:import:upload:*`, con validazione, limiti e annullamento. **Coerenza della sorgente.** Una copia può avere checksum corretti e contenere due tabelle osservate in istanti diversi. L’export usa una transazione repeatable-read sui percorsi SQL transazionali e una sessione snapshot per i documenti Mongo sulle topologie compatibili. Il catalogo Mongo viene letto a parte, quindi la struttura delle collezioni deve restare stabile durante la copia. Un Mongo standalone o tabelle MySQL non transazionali richiedono di sospendere le scritture per ottenere una copia coerente. La dichiarazione di coerenza e il confronto dei dati fanno parte della verifica. [Coerenza MongoDB](db/mongoTopologia.js) · [Garanzie per motore](docs/guida-export-import.md) · [Fedeltà e prerequisiti](docs/matrice-fedelta-export-import.md)

Lo scambio di schemi PostgreSQL può essere atomico. MySQL e MongoDB richiedono di considerare la finestra di promozione e le scritture concorrenti. Gli esiti `completato`, `ripristinato_dopo_errore` e `intervento_richiesto` distinguono successo, destinazione preservata o recuperata, e recupero incerto. Il preflight del restore valida l’intera catena prima del primo effetto. I file storici senza checksum hanno una verificabilità limitata. `verify` controlla integrità su disco. Per provare un cambiamento al codec o alla promozione, ripristina su un DB di prova e rileggi tramite un driver indipendente. ## Gateway MCP

Il client MCP parla Streamable HTTP con `/mcp`. La sessione di protocollo può aprire connessioni DB nominate tramite `connect_database`. Con RBAC attivo presenta una API key, tipicamente come `Authorization: Bearer …`. Il gateway verifica l’identità e l’impronta della credenziale sulle richieste successive e aggiorna il contesto dei permessi. Con RBAC attivo, per proseguire una sessione serve anche la credenziale corrispondente. Nella modalità locale con RBAC spento il gateway usa il principal root locale. Il limite di sessioni MCP è configurabile. Le strategie DB aperte tramite MCP e UI consumano lo stesso budget di 100 sessioni DB per istanza. Una scrittura tramite `execute_write` ha due passi. Il primo valida la proposta e restituisce un’anteprima da mostrare all’utente. Il client conserva il `confirm_token`. Dopo la conferma umana esplicita, la seconda chiamata presenta il token monouso. Il server ne verifica tipo e `connection_id`, consuma la prenotazione ed esegue l’operazione originale memorizzata con i permessi correnti. Il flag globale di sola lettura e quello della connessione sono controlli distinti. Per scrivere, la connessione salvata deve consentirlo esplicitamente e il gateway rilegge il flag prima dell’esecuzione. Scadenza e consumo liberano la prenotazione nella quota delle conferme. Per un nuovo tool che modifica dati, prova anche revoca tra anteprima ed esecuzione e doppia conferma concorrente. [Flusso di conferma](mcp/conferma.js) · [Quote](mcp/ConfirmQuota.js) · [Test delle conferme](test/unit-mcp-conferme-quota.js) · [E2E autorizzazioni MCP](test/e2e-rbac-mcp.js)

Il gateway monta gli strumenti con un wrapper comune per validazione, impostazioni, attività ed errori MCP. Mantieni la forma della risposta prevista dal protocollo, compresi gli errori strutturati degli strumenti. Se aggiungi una categoria di mutazione controlla anche le impostazioni centrali, l’anteprima, la classificazione nell’audit e il pannello di amministrazione del gateway. **Configurazione di rete.** L’installazione locale parte in loopback. Per condividere un’istanza la configurazione ordinaria richiede un reverse proxy che termini realmente HTTPS, la dichiarazione `CODEDB_TRUST_PROXY_TLS=1` e RBAC attivo. Il bind dei database è configurato separatamente. Per diagnosticare una connessione, individua il confine che fallisce fra handshake browser, login applicativo, apertura del tunnel e login al DBMS. ## Sviluppare e verificare una modifica

### Dal requisito ai file da cambiare

1. **Individua un caso osservabile.** Annota motore, bersaglio, tipo del valore, azione, risultato atteso e superficie. «Salvare `9007199254740993` in una colonna BIGINT e rileggerlo identico» permette di verificare un cambiamento al codec. «I numeri funzionano» lascia aperto quale rappresentazione è stata esercitata.
2. **Segui un percorso già usato.** Per una nuova modifica inline, cerca `doc:update` nei controller, negli handler, nella classificazione dei permessi e nei test. Per una nuova funzionalità nativa di un DBMS, parti dalla strategia e dai moduli del dialetto. Estendi il contratto comune solo se la nuova operazione appartiene a quel livello.
3. **Definisci i casi laterali che cambiano la soluzione.** Una lettura lenta deve tollerare il cambio di scheda. Una scrittura su chiave composta deve identificare una riga sola. Una migrazione deve poter leggere il formato precedente. Un’operazione confermata può perdere la risposta dopo aver scritto. Esercita i casi che esistono davvero per la funzione interessata.
4. **Individua un’osservazione indipendente.** Per il frontend controlla DOM, focus, payload e stato del documento. Per il driver rileggi i dati da una seconda connessione. Per il restore confronta dati, tipi, schema e vincoli sulla destinazione. Per un permesso prova sia un principal ammesso sia uno fuori scope.
5. **Verifica la sensibilità della prova.** Quando scrivi un test di regressione, eseguilo almeno una volta contro il difetto originale o una variante volutamente errata. Un esempio esistente è `node test/unit-import-conferma.js --mutant`, che salta in memoria la finalizzazione. Il test deve fallire perché manca la conferma dopo la verifica. L’esecuzione ordinaria dello stesso file deve passare. [Test di sensibilità](test/unit-import-conferma.js) · [Criteri del repository](AGENTS.md)
